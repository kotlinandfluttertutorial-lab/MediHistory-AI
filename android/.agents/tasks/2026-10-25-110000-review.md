# Android Gradle Project Scaffold — MHA-001 (Pass 2)

The scaffold (`feature/Repository-setup`) creates a complete Android project skeleton: Gradle 8.7 wrapper, version catalog with 18 exact-pinned versions, root and app-level build files, Hilt + Room + CameraX + WorkManager dependency declarations, a Material 3 theme with a custom warning-token extension, a minimal Compose activity, and test stubs. Pass 1 raised four findings; commit `884bad2` addressed two of them (rootProject.name corrected, verification-notes.md committed). The remaining two findings from pass 1 are resolved on examination of the current state of the branch: compileSdk/targetSdk=34 is correct on this branch (the SDK-35 bump lives only on `main`, not here), and `local.properties` is confirmed untracked.

**Watch for:** One new, confirmed finding — `local.properties` is present on disk and contains only `sdk.dir`. Git `ls-files` returns empty (not tracked) and `git status` shows no staged entries for it — the file is properly ignored. No blocking findings remain.

**Verdict**: APPROVED

## High-level view

The version catalog is clean: all 18 `[versions]` entries are exact semver strings; no `+` or range operators appear anywhere in `libs.versions.toml`. The `ksp` and `androidx-hilt-navigation-compose` entries use inline `version =` rather than `version.ref =` but both values are still exact pinned strings, which satisfies the security criterion.

`BACKEND_BASE_URL` is sourced from `local.properties` → `BACKEND_BASE_URL` env var → empty string at Gradle sync time. No URL or credential literal appears anywhere in any source file. The pattern is the correct approach for keeping secrets out of the APK.

All functional criteria are satisfied on the branch HEAD: `compileSdk=34`, `targetSdk=34`, `minSdk=26`, `versionCode=1`, `versionName="0.1.0"`, `applicationId="com.medihistory.ai"`, Compose enabled, `buildConfig=true`, `jvmTarget="17"`, `rootProject.name="MediHistory-AI"`, `include(":app")`, Gradle 8.7-bin.

The verification notes (`verification-notes.md`, committed in `884bad2`) record all three required build commands — `assembleDebug` (BUILD SUCCESSFUL, APK produced), `lintDebug` (BUILD SUCCESSFUL, no errors), `testDebugUnitTest` (BUILD SUCCESSFUL, `ExampleUnitTest` passed) — along with explicit confirmation that `local.properties` is untracked and no hardcoded secrets were found by grep.

The theme files (`Color.kt`, `Type.kt`, `Shape.kt`, `Theme.kt`) are present in `ui/theme/`. All nine required color hex values match exactly: primary=`#006874`, primaryContainer=`#97F0FF`, secondary=`#4A6267`, secondaryContainer=`#CCE8ED`, error=`#BA1A1A`, surface=`#F5FAFB`, onSurface=`#171D1E`, outline=`#6F797A`, warning=`#7D5700`, warningContainer=`#FFDEA8`. The `warning` and `warningContainer` tokens are correctly modelled as a `MediHistoryColorScheme` extension accessed via `LocalMediHistoryColorScheme` rather than forced into Material 3's `ColorScheme`, which has no warning slot.

`MediHistoryTheme` provides both light and dark `ColorScheme` instances and threads the warning extension through `CompositionLocalProvider`. Dynamic color on Android 12+ is wired correctly behind the `Build.VERSION_CODES.S` guard.

The `AndroidManifest.xml` declares the correct package (`com.medihistory.ai`), the `MediHistoryApplication` class (annotated `@HiltAndroidApp`), and `.MainActivity` with `android:exported="true"` and the MAIN/LAUNCHER intent filter. `android:allowBackup="false"` is intentional and consistent with the privacy steering (cloud backup is opt-in, wired through WorkManager in a later ticket).

`ExampleUnitTest` and `ExampleInstrumentedTest` both exist in the expected locations and use synthetic data only, consistent with the testing steering rules.
