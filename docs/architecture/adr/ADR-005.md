# ADR-005 — FastAPI over Django/Flask
**Date:** 2026-10-25  
**Status:** Accepted  
**Deciders:** Engineering team

## Context
The optional backend service needs to expose a REST API for cross-device sync, OCR proxying, and export orchestration. The backend must have strong type safety, auto-generated OpenAPI documentation, async support for I/O-bound operations (database, AI service calls), and first-class input validation. The team evaluated Python web frameworks as the target language is Python.

## Decision
Use FastAPI as the backend framework, with:
- Pydantic v2 typed schemas for all request and response bodies.
- Alembic for all database migrations (no manual SQL).
- Async SQLAlchemy with asyncpg driver for PostgreSQL.
- `slowapi` (or equivalent ASGI middleware) for rate limiting.
- JWT-based authentication applied to every protected route via a shared `get_current_patient` dependency.
- All secrets loaded from environment variables via `core/config.py`.
- OpenAPI annotations on every endpoint.

## Consequences
### Positive
- Pydantic schemas give compile-time-like validation and serialisation without extra tooling.
- Auto-generated OpenAPI/Swagger docs are always in sync with the code.
- Native async/await support with standard Python `asyncio` — no threading complexity.
- High performance for I/O-bound workloads (AI service proxying, database reads).
- Straightforward dependency injection system for auth, database sessions, and service instances.

### Negative / Trade-offs
- Smaller ecosystem than Django; some batteries (admin panel, ORM) must be added separately.
- Alembic migration authoring requires more manual care than Django's auto-migrations.
- Less opinionated than Django; team must establish conventions explicitly (covered by this and other ADRs).

## Alternatives Considered
| Alternative | Reason rejected |
|---|---|
| Django REST Framework | Heavier, more opinionated; Django ORM does not compose as cleanly with async; auto-generated OpenAPI support requires third-party packages. |
| Flask + marshmallow | No native async; validation schema separate from route definitions increases divergence risk; no built-in OpenAPI generation. |
| Express (Node.js) | Different language from the AI/OCR toolchain; adds a second runtime to operate and maintain. |
