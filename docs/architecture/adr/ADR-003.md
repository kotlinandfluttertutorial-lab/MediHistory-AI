# ADR-003 — WorkManager for Background OCR
**Date:** 2026-10-25  
**Status:** Accepted  
**Deciders:** Engineering team

## Context
OCR processing involves sending a document image to a remote AI/OCR service and receiving structured JSON in return. This round-trip typically takes 10–30 seconds. The process must survive the user backgrounding the app, device reboots, and brief network outages. It must also respect battery and network constraints.

## Decision
Use WorkManager (`androidx.work.WorkManager`) for all background OCR, sync, and export jobs:
- `OcrWorker` — triggered after a prescription document is stored. Uses `NetworkType.CONNECTED`. Retries up to 3 times with exponential backoff. Uses `EXPEDITED` work type so it runs at foreground-like priority without requiring a persistent foreground service notification.
- `SyncWorker` — periodic background sync. Constrained to `NetworkType.CONNECTED` and `BatteryNotLow`.
- `ExportWorker` — one-time, on-demand PDF/ZIP generation.

## Consequences
### Positive
- Work is guaranteed to execute even after app process death or device reboot.
- Built-in constraint system (network, battery, storage) avoids manual checks.
- EXPEDITED work type gives OCR near-foreground-service priority without a persistent notification.
- Retry and backoff policies are declarative and testable.
- Compatible with Hilt injection via `HiltWorker`.
- `TestWorkerBuilder` enables integration tests without a real device.

### Negative / Trade-offs
- WorkManager adds latency compared to running a coroutine in the ViewModel directly — not suitable for sub-second operations.
- Doze mode and App Standby may still delay non-expedited work on some OEMs.
- Workers must be idempotent; extra care needed when writing OCR results to Room to avoid duplicates on retry.

## Alternatives Considered
| Alternative | Reason rejected |
|---|---|
| Coroutines only (viewModelScope / lifecycleScope) | Work is cancelled when the app process is killed; OCR jobs would be lost on backgrounding. |
| JobScheduler (direct) | Lower-level API; WorkManager is the recommended abstraction and handles backward compatibility. |
| Foreground service | Requires a persistent notification for the full OCR duration; poor UX for a 10–30 s operation; EXPEDITED WorkManager achieves similar priority without a permanent notification. |
