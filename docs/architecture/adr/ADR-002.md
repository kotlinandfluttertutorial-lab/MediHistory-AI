# ADR-002 — Room over Raw SQLite
**Date:** 2026-10-25  
**Status:** Accepted  
**Deciders:** Engineering team

## Context
The app requires a reliable, type-safe local database to store prescriptions, medicines, duplicate alerts, reminders, and audit log entries. The database must support complex queries, foreign key enforcement, multi-table transactions, and versioned migrations. Developers need compile-time verification of SQL queries.

## Decision
Use Room (Jetpack Room persistence library) as the local database layer, with:
- Entity classes annotated with `@Entity`; DAO interfaces annotated with `@Dao`.
- All multi-table writes wrapped in `@Transaction`.
- Foreign keys enforced (`onDelete = CASCADE` for child records).
- Migrations versioned and committed; `fallbackToDestructiveMigration()` disabled in **all environments** (debug, staging, and production) — data loss on schema mismatch is never acceptable regardless of build type.
- Room schema JSON exports committed to `android/app/schemas/` for migration validation in CI.
- Database encryption (SQLCipher or equivalent) to be evaluated before production, per NFR-006.

## Consequences
### Positive
- Compile-time verification of SQL queries reduces runtime errors.
- Migration framework ensures safe, versioned schema changes.
- Coroutine and Flow integration works natively with Kotlin async patterns.
- Strongly typed entities and DAOs reduce boilerplate compared to raw SQLite.
- Large community, official Google support, and extensive documentation.

### Negative / Trade-offs
- Room adds a compile-time annotation processing step (kapt/KSP), increasing build times slightly.
- Some complex dynamic queries are awkward to express in Room and may require `@RawQuery`.
- Encryption (SQLCipher) requires a third-party dependency and additional key management work.

## Alternatives Considered
| Alternative | Reason rejected |
|---|---|
| Raw SQLite (android.database.sqlite) | No compile-time query verification; migration management is entirely manual; far more boilerplate. |
| Realm | Third-party dependency; different object model from the rest of the Jetpack stack; migration story is less standard. |
| SQLDelight | Good type-safety, but less Jetpack integration; team has stronger Room experience; official Android guidance favours Room. |
