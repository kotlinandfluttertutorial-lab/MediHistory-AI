# ADR-004 — CameraX over Camera1/Camera2
**Date:** 2026-10-25  
**Status:** Accepted  
**Deciders:** Engineering team

## Context
The app needs to capture prescription images using the device camera. Camera behaviour varies significantly across Android versions (5.0–14+) and OEM firmware. The implementation must handle focus, flash, orientation, and aspect ratio consistently, and must work reliably on both old and new devices without per-device workarounds.

## Decision
Use CameraX (`androidx.camera`) with the `ImageCapture` use case:
- `ImageCapture` use case for still-image capture (JPEG output).
- `Preview` use case bound to a `PreviewView` composable.
- Confirmation screen shown before storing the captured image.
- Original image stored unchanged in app-private storage before OCR is triggered.
- Mock CameraX output used in tests — no real device required.

## Consequences
### Positive
- CameraX handles device-specific quirks and compatibility differences internally.
- Lifecycle-aware — camera is automatically released when the composable leaves the screen.
- Consistent API across Android 5.0+ without explicit Camera1/Camera2 branching.
- Official Google support and active maintenance.
- Easy to test with mock CameraX output.

### Negative / Trade-offs
- Adds a dependency on the CameraX Jetpack library (pinned exact version in `libs.versions.toml`).
- Advanced camera controls (manual exposure, RAW capture) are less accessible than direct Camera2.
- Occasional delays in CameraX receiving upstream Camera2 feature updates.

## Alternatives Considered
| Alternative | Reason rejected |
|---|---|
| Camera2 API directly | Too much boilerplate; device-specific workarounds required; lifecycle management is manual and error-prone. |
| Third-party camera libraries (e.g. Fotoapparat, ZXing) | Additional dependency risk; less active maintenance; CameraX is the official recommended solution. |
