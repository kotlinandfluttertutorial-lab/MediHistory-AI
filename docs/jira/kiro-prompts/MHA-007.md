## Implementation Boundaries (what NOT to do)
- Do not implement biometric authentication (deferred from MVP).
- Do not store the session token in plaintext `SharedPreferences` — use `EncryptedSharedPreferences`.
- Do not log the token to Logcat or any backend log.
- Do not implement password reset or registration flows (not in scope for this ticket).
- Do not implement features beyond this ticket's scope.
- Do not bypass the repository pattern or call Room/API directly from UI.
- Do not add clinical advice, diagnoses, or treatment recommendations.
- Do not hardcode credentials or API keys.

## Required Tests
### Unit Tests
- Verify session token is stored in `EncryptedSharedPreferences`, not plaintext.
- Verify `AuthViewModel` emits `Loading`, `Success`, and `Error` states correctly.
- Verify JWT expiry detection triggers navigation to login screen.

### Integration Tests
- Backend: valid credentials return a JWT with correct patient scope.
- Backend: invalid credentials return HTTP 401 with no token.
- Backend: protected route without JWT returns HTTP 401.

### UI Tests (if applicable)
- UI: login form submits with valid credentials and navigates to dashboard.
- UI: login form shows error message on 401 response.

### Security Tests (if applicable)
- Verify token is not visible in Logcat (grep for token pattern in log output).
- Verify expired token returns 401 on the next API request.
- Verify no token is stored in plaintext SharedPreferences.
