## Implementation Boundaries (what NOT to do)
- Do not implement the PDF preview screen — that is MHA-056.
- Do not implement the consent and share flow — that is MHA-057.
- PDF generation must work entirely offline — no network access.
- Disclaimer text must be verbatim: "This document is a patient-compiled record and is not a clinical report."
- PDF must contain only data selected by the patient; no unrequested data may be included.
- Evaluate iText against its AGPL licensing before using it; prefer Android PdfDocument if licensing is a concern.
- Do not add diagnosis, prescribing logic, dose optimisation, or auto-medication changes.
- Do not hardcode credentials or API keys.
- Do not use real patient data in tests; use synthetic fixtures only.

## Required Tests
### Integration Tests
- Generate a PDF with two selected medicines: verify content includes both.
- Verify disclaimer text is present in the PDF output.

### Negative Tests
- Remove network access and verify PDF generation still succeeds.

### Security Tests
- PDF does not contain data from items not selected by the patient.
