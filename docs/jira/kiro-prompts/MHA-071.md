# MHA-071 — Account deletion — local and backend data removal

## Jira Ticket
- **ID:** MHA-071
- **Epic ID:** MHA-E11
- **Epic Name:** Security, Privacy, and Data Management
- **Summary:** Account deletion — local and backend data removal
- **Description:** Implement the account deletion flow: patient navigates to Settings → Delete Account. A plain-language warning explains what will be deleted and that backup copies have separate retention limitations. After confirmation: delete all local Room records, source document files, WorkManager jobs, notifications, and EncryptedSharedPreferences. Send a deletion request to the backend if sync is enabled. App returns to onboarding.

## Implementation Boundaries (what NOT to do)
- Do not silently delete data without the warning confirmation step.
- Do not delete data before the patient confirms.
- Do not implement data export — that is MHA-070.
- Do not implement cloud backup — that is MHA-072.
- Do not bypass the repository pattern or call Room directly from UI.
- Do not hardcode credentials or API keys.
- Do not use real patient data in tests; use synthetic fixtures only.
