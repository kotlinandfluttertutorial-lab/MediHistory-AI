## Implementation Boundaries (what NOT to do)
- Do not implement the history generation service — that is MHA-049.
- Do not implement the history list or detail UI screens — those are MHA-050 and MHA-051.
- Do not implement the generate summary trigger — that is MHA-052.
- Generating a new summary must NOT overwrite previous versions; version must increment.
- Do not add diagnosis, prescribing logic, dose optimisation, or auto-medication changes.
- Do not bypass the repository pattern or call Room directly from UI.
- Do not hardcode credentials or API keys.
- Do not use real patient data in tests; use synthetic fixtures only.
