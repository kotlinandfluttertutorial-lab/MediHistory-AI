## Implementation Boundaries (what NOT to do)
- Do not implement OCR error handling and retry — that is MHA-031.
- Do not implement the manual entry screen — that is MHA-032.
- Editing a field must store the new value in `patientValue` — never overwrite `rawValue`.
- Do not add diagnosis, prescribing logic, dose optimization, or auto-medication changes.
- Do not auto-confirm or auto-reject any field; all actions must be patient-initiated.
- Do not hardcode navigation route strings; use the Routes object.
- Do not bypass the repository pattern or call Room directly from UI.
- Do not hardcode credentials or API keys.
- Do not refactor unrelated screens.

## Required Tests
### Unit Tests
- Confirm action transitions `reviewState` to REVIEWED.
- Edit action stores new value in `patientValue` without changing `rawValue`.
- Reject action transitions `reviewState` to REJECTED.

### Integration Tests
- Save updates Room `reviewState` correctly.

### UI Tests
- All fields are visible at 360 dp screen width without horizontal scrolling.
- Confidence indicator is not colour-only (includes numeric percentage or text label).

### Accessibility Tests
- Confidence indicator conveys information through text, not colour alone.
- Save button has a minimum 48×48 dp touch target.
