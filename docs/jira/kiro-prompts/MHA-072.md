# MHA-072 — Cloud backup — opt-in, status, and encryption

## Jira Ticket
- **ID:** MHA-072
- **Epic ID:** MHA-E11
- **Epic Name:** Security, Privacy, and Data Management
- **Summary:** Cloud backup — opt-in, status, and encryption
- **Description:** Implement the cloud backup feature as opt-in only. Settings screen (SCR-26) shows backup status: enabled/disabled, last successful backup timestamp, last error. Enabling backup requires explicit patient confirmation. Backup is encrypted on-device before upload (using Keystore-derived key). Disabling backup shows what happens to existing cloud copies.

## Implementation Boundaries (what NOT to do)
- Do not enable backup by default — opt-in is required.
- Do not upload backup without the explicit consent step.
- Do not store the backup encryption key outside the Android Keystore.
- Do not implement account deletion — that is MHA-071.
- Do not implement data export — that is MHA-070.
- Do not bypass the repository pattern or call Room directly from UI.
- Do not hardcode credentials or API keys.
- Do not use real patient data in tests; use synthetic fixtures only.

## Required Tests
### Integration Tests
- Backup is disabled by default on a fresh install.
- Enabling backup shows a plain-language consent dialog before proceeding.
- After backup completes, verify the payload is encrypted (not readable as plaintext).
- Disabling backup shows the cloud retention explanation.

### Security Tests
- Backup payload is not readable as plaintext after upload.
