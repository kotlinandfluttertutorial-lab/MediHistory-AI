# MHA-070 — Data export — encrypted ZIP with all patient data

## Jira Ticket
- **ID:** MHA-070
- **Epic ID:** MHA-E11
- **Epic Name:** Security, Privacy, and Data Management
- **Summary:** Data export — encrypted ZIP with all patient data
- **Description:** Implement the data export feature: patient can trigger an export from the Settings screen (SCR-25). Export produces an encrypted ZIP containing: prescription images, prescription metadata JSON, extracted medicine data JSON, history summaries JSON, dose log JSON, audit log metadata JSON. Encryption key is derived from a patient-provided passphrase (not stored on device). Export progress is shown.

## Implementation Boundaries (what NOT to do)
- Do not store the patient passphrase on-device after export completes.
- Do not include data not selected/owned by the patient in the export.
- Do not implement account deletion — that is MHA-071.
- Do not implement cloud backup — that is MHA-072.
- Do not bypass the repository pattern or call Room directly from UI.
- Do not hardcode credentials or API keys.
- Do not use real patient data in tests; use synthetic fixtures only.

## Required Tests
### Integration Tests
- Export produces a ZIP containing all required data categories (prescription images, metadata JSON, medicines JSON, history JSON, dose log JSON, audit log JSON).
- Passphrase is not found in SharedPreferences or logs after export.
- Wrong passphrase fails decryption.
- Export works without network access (offline test).

### Security Tests
- Passphrase not stored on device after export (checked via SharedPreferences and file system inspection).
