## Jira Ticket

- **Summary:** OCR service interface and WorkManager job
- **Description:** Define the OcrService interface (extract(documentPath: String, mimeType: String): OcrResult) and OcrResult data class (fields: List of ExtractedField, overallConfidence, rawText, errorMessage nullable). ## Implementation Boundaries (what NOT to do)
- Do not implement a specific OCR provider (ML Kit, Cloud Vision, etc.) — the interface must remain provider-independent.
- Do not implement the confidence scoring entity (ExtractedField Room entity) — that is MHA-029.
- Do not implement the OCR review UI — that is MHA-030.
- Do not implement OCR error UI — that is MHA-031.
- Do not make real network calls in unit tests; use the FakeOcrService.
- Do not log document text or raw OCR content.
- Do not add diagnosis, prescribing logic, dose optimization, or auto-medication changes.
- Do not infer missing dose, duration, diagnosis, allergy, or medicine status from OCR output.
- Do not hardcode credentials or API keys.
- Do not refactor unrelated modules.

## Required Tests
### Unit Tests
- OcrWorker with FakeOcrService updates OcrStatus to NEEDS_REVIEW on success.
- OcrWorker with FakeOcrService updates OcrStatus to ERROR when OcrService throws.
- OcrWorker sets OcrStatus to PROCESSING at the start of execution.
- OcrResult validation rejects malformed outputs (missing required fields).

### Security Tests
- OcrWorker does not log document text (verify no log calls contain rawText).

### Negative Tests
- OcrWorker sets ERROR status when OcrService throws an exception.
- Repeated failures do not multiply WorkManager jobs.
