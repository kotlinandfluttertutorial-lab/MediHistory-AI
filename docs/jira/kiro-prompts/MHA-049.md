## Jira Ticket
- **ID:** MHA-049
- **Epic ID:** MHA-E07

- **Summary:** History generation service interface and AI summarisation integration
- **Description:** Define the HistoryGenerationService interface (generate(patientId, reviewedRecords): HistoryGenerationResult). ## Implementation Boundaries (what NOT to do)
- Do not implement the history list or detail UI — those are MHA-050 and MHA-051.
- Do not implement the generate summary trigger UI — that is MHA-052.
- Do not implement the backend history API endpoints — that is MHA-053.
- The system prompt must explicitly prohibit inventing diagnoses, allergies, or treatment history.
- Missing fields must be omitted, not inferred — never fabricate medical data.
- The system prompt must not be overridable by user-supplied data.
- Do not add prescribing logic, dose optimisation, or auto-medication changes.
- Do not hardcode API keys or secrets; use environment variables.
- Do not use real patient data in tests; use synthetic fixtures only.
