## Implementation Boundaries (what NOT to do)
- The offline indicator must NOT appear during purely local CRUD operations (create/edit patient or doctor) — only during sync-related operations.
- Do not break core patient/doctor CRUD functionality when network is unavailable.
- Do not implement actual cloud sync in this ticket — that is MHA-072.
- Do not implement features beyond this ticket's scope.
- Do not bypass the repository pattern or call Room/API directly from UI.
- Do not add clinical advice, diagnoses, or treatment recommendations.
- Do not hardcode credentials or API keys.

## Required Tests
### Unit Tests
- Verify all `PatientDao` and `DoctorDao` operations succeed without network.

- Create and edit a patient with airplane mode enabled — verify data is saved and displayed correctly.

### UI Tests (if applicable)

- Negative: offline indicator does not appear during local create/edit operations.

### Security Tests (if applicable)
