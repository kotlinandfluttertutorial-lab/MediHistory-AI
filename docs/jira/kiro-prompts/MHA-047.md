## Implementation Boundaries (what NOT to do)
- Do not implement the duplicate detection algorithm — that is MHA-041 and MHA-046 (Android-side).
- Do not implement the alert list or detail UI screens — those are MHA-043 and MHA-044.
- Cross-patient access must return 404 (not 403) to avoid leaking resource existence.
- Do not store prescription text, medicine details, or document content in API logs.
- Do not add diagnosis, prescribing logic, dose optimisation, or auto-medication changes.
- Do not hardcode credentials, API keys, or secrets in any file.
- Do not use real patient data in tests; use synthetic fixtures only.

## Required Tests
### Positive Tests
- List, detail, review, and unreview all return correct HTTP status codes and response bodies.

### Security Tests
- Cross-patient access on GET /alerts/{id} returns 404.
- Unauthenticated request to any endpoint returns 401.

### Negative Tests
- PATCH /alerts/{id}/review on an already-reviewed alert is idempotent (returns success, not an error).
