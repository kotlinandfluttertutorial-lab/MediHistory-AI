## Implementation Boundaries (what NOT to do)
- Do not show a "no interactions found" message in the unavailable state — that would imply a check was performed.
- Do not show partial results under any circumstances when the provider is unavailable.
- Do not add reassuring language that implies the medicines are safe.
- Do not implement provider configuration UI — that is MHA-067.
- Do not bypass the repository pattern or call Room directly from UI.
- Do not hardcode credentials or API keys.
- Do not use real patient data in tests; use synthetic fixtures only.

## Required Tests
### Unit Tests
- Exact required message text is visible when available = false.
- No result list component is rendered in unavailable state.

### Accessibility Tests
- Unavailable message is announced correctly by TalkBack.
