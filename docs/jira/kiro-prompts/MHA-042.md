- Do not implement the Mark as Reviewed action — that is MHA-045.
- Do not implement combination product handling — that is MHA-046.
- Labels for alerts must say "Potential duplicate" — never use language implying clinical certainty.
- Do not add diagnosis, prescribing logic, dose optimization, or auto-medication changes.
- Do not create duplicate DuplicateAlert records for the same medicine pair.
- Do not call any backend API in this ticket — this is the local Room data layer only.
- Do not bypass the repository pattern or call Room directly from UI.
- Do not hardcode credentials or API keys.
- Do not use real patient data in tests; use synthetic fixtures only.

## Required Tests
### Integration Tests
- Add two medicines with the same active ingredient: verify one DuplicateAlert record is created.
- Reject one medicine (set ReviewState to REJECTED): verify the associated alert is voided.

### Unit Tests
- DuplicateAlert is not created twice for the same medicine pair (idempotent insertion).
- DuplicateAlert entity has all required fields.

### Security Tests
- `listByPatient` with a different `patientId` returns an empty list (cross-patient isolation).
