## Implementation Boundaries (what NOT to do)
- Do not implement the history generation service logic — that is MHA-049.
- Do not implement the history UI screens — those are MHA-050 and MHA-051.
- Cross-patient access must return 404 (not 403) to avoid leaking resource existence.
- Do not store prescription text, medicine details, or document content in API logs.
- Do not add diagnosis, prescribing logic, dose optimisation, or auto-medication changes.
- Do not hardcode credentials, API keys, or secrets in any file.
- Do not use real patient data in tests; use synthetic fixtures only.

## Required Tests
### Positive Tests
- POST /history/generate returns HTTP 202 and a job ID.
- GET /history returns all versions for the authenticated patient.
- GET /history/{id} returns sections with sourceRefs.

### Security Tests
- Cross-patient access on GET /history/{id} returns 404.
- Unauthenticated request returns 401.

### Negative Tests
- Invalid history ID returns 404.
